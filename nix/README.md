# Nix reference

Import `nixosModules.default` and set `services.nixSecrets.enable`. The
[README](../README.md#configure-a-target) has a complete example. Machine
secrets go under `services.SERVICE.secrets` and per-user secrets under
`userServices.USER.SERVICE.secrets`. A secret tree can nest:

```nix
services.nixSecrets.services.mail.secrets.backup = {
  _recipientNames = [ "backup-operator" ];
  passphrase = {
    valueType = "password";
    destination = {
      path = "/persistent/secrets/mail/backup/passphrase";
      category = "backup";
      owner = "mail-backup";
      group = "mail-backup";
      mode = "0400";
    };
  };
};
```

This leaf's identifier is `HOST.services.mail.backup.passphrase`. Per-user
leaves are `HOST.user-USER-services.SERVICE.PATH`.

## Leaves

A destination path must be `/persistent/secrets/SERVICE/CATEGORY/NAME`, where
CATEGORY is `setup`, `service` or `backup`. The mode must be `0400` or
`0440`. Paths must be unique on a host.
`destination.contentType` may be `openssh-private-key`, `openssh-public-key` or
`named-ssh-ed25519-public-keys`. The store keeps the public half of an OpenSSH
private key in plaintext.

| Leaf option | Meaning |
| --- | --- |
| `valueType` | `"password"` makes the leaf generatable. `"key"` only classifies it. |
| `description` | Text shown to the operator. |
| `humanFacing` | The value is used by a person. |
| `externalInputRequired` | The operator must enter the value. It is never generated. |
| `optional` | The leaf may stay unset without blocking its consumers. |
| `generateOnDeploy` | Set to false to never generate the value. |
| `valueGenerator` | Exact format of a generated value. |
| `consumerConstraints` | Limits of the consuming program for typed passwords. |
| `derivedFrom` | Deploy a framed copy of another secret. |
| `requiredForInstall` | Evaluation fails while the value is unset. |

`consumerConstraints` requires `valueType = "password"`. It takes
`cannotHandleShorterThan`, `cannotHandleLongerThan` and `matchingRegex`.

`displayPath` on a service, and `identity` and `presentation` on a leaf, change
only how the TUI groups and names entries.

## Recipients

Name keys in `recipientPublicKeys = { primary = "ssh-ed25519 ..."; }` and select
them with `defaultRecipientNames`, service or leaf `recipientNames`, or subtree
`_recipientNames`. Lists of keys work the same way in
`defaultRecipientPublicKeys`, `recipientPublicKeys` and `_recipientPublicKeys`.
Keys must be `ssh-ed25519` or `ssh-rsa`. Rotating a named key keeps old records
readable.

## Generation

During deployment the target generates an unset leaf if it has
`valueType = "password"` or a `valueGenerator`, and is not public information,
`externalInputRequired` or `generateOnDeploy = false`. A password is 32
characters long, or as long as `consumerConstraints` allow. The target never
replaces an existing value. Set `generateOnDeploy = false` on a value that two
hosts must share.

```nix
valueGenerator = {
  kind = "random-bytes";
  bytes = 32;               # 16 to 1024
  encoding = "base64";      # "base64" (padded), "base64url" (unpadded) or "hex"
  prefix = "";              # at most 1024 bytes
  suffix = "\n";            # at most 1024 bytes
};
```

The value is `prefix + encode(random bytes) + suffix`. A `valueGenerator` cannot
be combined with a `contentType`.

## Derived values

```nix
secrets.credentials = {
  destination = { /* path, category, owner, group, mode */ };
  derivedFrom = {
    identifier = "HOST.services.app.token";
    prefix = "token=";
    suffix = "\n";
    # tomlPath = [ "authentication" "token" ];  # string field of a TOML source
    # encoding = "pgpass";                       # escape : and \
  };
};
```

The leaf deploys `prefix + source + suffix` and has no stored value of its own.
The source cannot itself be derived. With `encoding = "pgpass"`, a source with
a line break or NUL is an error. If the source is unset and generatable, the
deployment generates it. A source owned by another host is generated by the
first host deployed and stored under the source identifier.

## Operator-only values

```nix
services.nixSecrets.services.signing.secrets.private-key = {
  kind = "operator";
  signingOnly = true;
  generator = {
    installable = "github:owner/signing-tool#signer";
    args = [ "keygen" "--stdio" ];
  };
};
```

An operator leaf is stored but never deployed. The optional generator runs on
the operator machine as `nix run INSTALLABLE -- ARGS` with empty stdin. It must
exit 0, write the private key to stdout (at most 1 MiB) and the public key to
fd 3 (at most 64 KiB). `signingOnly = true` restricts the key to
`sign-artifacts` and `sign-closure`. Its plaintext is never released.

`lib.operatorPublicKey STORE IDENTIFIER` returns the stored public key as
base64, or null. `lib.requireOperatorPublicKey` fails where that returns null.

## Install prerequisites

Set `storeFile = toString ./nix-secrets.toml;`. Evaluation then fails, naming
the identifier, while a leaf with `requiredForInstall = true` or an identifier
listed in `requiredBeforeInstall` has no value in that file. An operator key
with a generator needs its public half, and a public-info leaf needs its record
or a default. `requiredForInstall` cannot be set on an optional or derived
leaf. `storeFile` defaults to `publicInfoInventoryFile`.

## Public information

A leaf with `kind = "public-info"` holds pinned known-hosts lines in plaintext,
under `[public_info."ID"]` in `nix-secrets.toml`. It sets
`sharedPublicId = "ID"` (two path components), `expectedSshHost`,
`expectedSshPort` and optionally `expectedSshHosts`. Its destination must be
`/persistent/public-info/ID` with category `public-info`, owner and group
`root`, mode `0644` and `contentType = "ssh-known-hosts"`. Several hosts can
deploy the same record if their leaves use the same settings, and each target
checks the host, port and key format. Several hosts or key lines need receiver
protocol 4.

`installDefaultIfMissing = true` with `publicInfoInventoryFile` set installs
the stored value, or `defaultValue`, at boot if the destination does not exist.

`deployment.publishHostIdentityTo` names one of this host's public-info leaves
by identifier. Deploying the host fills it with the host key the TUI verified.
Replacing an existing value needs separate approval.

## Target-local SSH keys

A leaf with `generatedSecret = { type = "local-ssh-key"; output = { ... }; }`
makes the target generate an Ed25519 key, or keep its existing one. `output`
takes the fields of a destination. The private key stays on the target, and
its public key is stored. `generatedSecret.registerAt` names a leaf with
`contentType = "named-ssh-ed25519-public-keys"` and `authorizedForUser` that
collects these public keys.

[Storage Box keys](../STORAGE-BOX-BOOTSTRAP.md) are another generated type.

## Host options

`receiver.enable` installs the socket-activated receiver.
`forwarder.enable` creates the `nix-secrets-forward` account, restricted to the
receiver, for `forwarder.authorizedKeys`. It requires the receiver and OpenSSH.

Each successful deployment writes a record without values to
`receiver.auditDirectory` (`/run/nix-secrets/audit`). `receiver.auditGroup` may
read it. `receiver.postDeployCommand` is a `/nix/store` executable that runs
after publication. If it fails, the deployment reports failure and the new
values stay installed.

`services.secretsReadyWaiter.enable` creates one waiter unit per service. Only
the units in `consumerUnits` get `Requires=` and `After=` on it.

`config.services.nixSecrets.evaluated` is the public inventory.
`config.system.build.nixSecretsManifest` is the host's manifest, installed at
`/etc/nix-secrets/manifest.json`.
